## CONTENT EXPERIENCE FRAMEWORK

### Three pillars (frog/Capgemini)

1. **Audience** — Design around mode and moment of need
2. **Content Qualities & Types** — GEO/LLM surfacing, high-impact formats
3. **Content Orchestration** — Activation across owned, third-party, and ecosystem

### Audience behavior modes

| Mode | Priority | Description |
|------|----------|-------------|
| Ad-hoc information searchers | HIGH | Quick, reliable answers to specific scientific questions in flow of work |
| Evidence explorers | HIGH | Explore implications, validate understanding, follow citations |
| Scientific interpreters | MEDIUM | Critically analyse, compare, contextualise evidence |
| Patient-facing translators | LOW | Prepare to explain scientific information in patient conversations |
| Mastery-driven learners | DE-PRIORITIZE | Formal learning; dubious of pharma-led content |

### High-priority content types

- **Core research with layered depth** — pre-generated key insights (3–5 bullets),
  clear structure (summary → explanation → evidence → links), inline citations,
  visible provenance, time signal
- **Short-form video** — 3–5 min max, visually-led, skippable, captioned, full
  transcript, segmented chapters
- **Infographics & quick visuals** — rapid visual understanding, text equivalents,
  built on-site for AI readability
- **AI retrieval chat** — answer-first, retrieval-based (not generative), cited
  responses, pre-defined prompts
- **Patient-ready explainers** — simplified language, inline citations,
  ready-to-share for patient interactions

### De-prioritized content types

- Long-form e-learning modules
- PDF static documents
- Long-form audio/podcast
- Long-form traditional research formats

### AI-native content structuring — 4 principles

1. **Open, crawlable pages** — no login barriers; full content served without auth
2. **Clear structure** — single H1, summary paragraph, semantic sections, H3
   subsections for narrow query retrieval
3. **Machine-readable formats** — HTML-first data, machine-readable dates,
   structured metadata, evidence type classification
4. **Citation-ready design** — DOI-linked inline citations, full reference list
   in HTML, schema markup, marked-up key takeaway boxes

### Content orchestration — ecosystem model

MedVerse operates as a scientific intelligence layer within a broader ecosystem:

- **Discovery channels:** General LLMs (Gemini, Claude, ChatGPT), Medical LLMs
  (OpenEvidence, UpToDate, MedAI, DermAI, Heidi, Doximity)
- **Validation channels:** Journals (Medscape, PubMed, NEJM, JAMA)
- **MedVerse core:** Standardized medical information across TAs; LLM & third-party
  ready; bi-directional links to program sites
- **Program sites:** ADVENT, IMMERSE, Br1dge, RDU, Nerve Nexus — retain branded identity
- **Activation:** Social, congress content, field reps

## HCP RESEARCH FINDINGS

12 HCPs interviewed (US, France, Germany) — generalists + specialists, range of
digital/AI adoption.

### 5 key insights

1. **AI use is widespread but segmented** — orientation, memory refresh, clinical
   reasoning. Human judgement remains final authority.
2. **Trust collapses when AI overreaches** — single negative experience can cause
   tool abandonment. Hallucinations viewed worse than stated limitations.
3. **Pharma content trusted for clinical decisioning, NOT learning** — ~90% would
   NOT trust pharma for traditional learning modules.
4. **UpToDate remains the gold standard** — used at least once per shift; HCPs
   start with Google/AI, then confirm on UpToDate.
5. **Visual structure outperforms narrative** — HCPs scan for answers, do not read
   sequentially.

### 5 implications for MedVerse

1. Don't replace UpToDate — position as Sanofi-specific layer
2. Focus where Sanofi can differentiate (product info, device training, access)
3. Treat external LLMs as primary discovery channels
4. Build AI-enabled hub to RAG all Sanofi content with visible citations
5. Gating is a liability unless it clearly adds value
